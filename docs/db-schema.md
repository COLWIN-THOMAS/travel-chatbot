# Database Schema (PostgreSQL)

## users
| Column         | Type                     | Notes                          |
|----------------|--------------------------|---------------------------------|
| id             | UUID, primary key        | default gen_random_uuid()      |
| email          | TEXT, unique, not null   |                                  |
| password_hash  | TEXT, not null           | never store plaintext passwords |
| created_at     | TIMESTAMP, default now() |                                  |

## trips
| Column        | Type                         | Notes                                    |
|----------------|------------------------------|-------------------------------------------|
| id             | UUID, primary key            | default gen_random_uuid()                 |
| user_id        | UUID, FK → users.id          | ON DELETE CASCADE                          |
| destination    | TEXT, not null               |                                             |
| budget_total   | NUMERIC, not null            |                                             |
| days_count     | INTEGER, not null            |                                             |
| preferences    | TEXT[]                       | e.g. {"food","adventure"}                  |
| status         | TEXT, not null, default 'planning' | 'planning' \| 'active' \| 'completed' |
| created_at     | TIMESTAMP, default now()     |                                             |

## days
| Column       | Type                      | Notes                              |
|--------------|---------------------------|--------------------------------------|
| id           | UUID, primary key         | default gen_random_uuid()           |
| trip_id      | UUID, FK → trips.id       | ON DELETE CASCADE                    |
| day_number   | INTEGER, not null         |                                       |
| date         | DATE, nullable            |                                       |

Unique constraint: (trip_id, day_number) — a trip can't have two "Day 2"s.

## itinerary_items
| Column         | Type                      | Notes                                          |
|----------------|---------------------------|--------------------------------------------------|
| id             | UUID, primary key         | default gen_random_uuid()                        |
| day_id         | UUID, FK → days.id        | ON DELETE CASCADE                                 |
| place_name     | TEXT, not null            |                                                    |
| category       | TEXT, not null            | 'hotel' \| 'restaurant' \| 'attraction' \| 'transport' |
| estimated_cost | NUMERIC, not null         | set by the itinerary generator                    |
| visited        | BOOLEAN, not null, default false |                                              |
| order_in_day   | INTEGER, not null         |                                                    |
| notes          | TEXT, nullable            |                                                    |

No actual_cost column — per data-model.md, actual spend is derived by summing
the expenses table (next step), not stored here.

## expenses
| Column             | Type                      | Notes                                    |
|--------------------|---------------------------|---------------------------------------------|
| id                 | UUID, primary key         | default gen_random_uuid()                    |
| trip_id            | UUID, FK → trips.id       | ON DELETE CASCADE                             |
| itinerary_item_id  | UUID, FK → itinerary_items.id, nullable | null = unplanned spend (e.g. "bought water") |
| amount             | NUMERIC, not null         |                                                |
| category           | TEXT, nullable            | e.g. "food", "transport", "shopping"          |
| logged_at          | TIMESTAMP, default now()  |                                                |

## chat_sessions
One row per conversation. Holds the state-machine position and the details collected so far, so the server
remembers earlier answers before any trip exists.

| Column | Type | Notes |
|---|---|---|
| id | UUID, primary key | generated by the client |
| user_id | UUID, FK → users.id | ON DELETE CASCADE, indexed |
| state | TEXT, not null | `COLLECTING` \| `CONFIRM` \| `POST_PLAN` |
| slots | JSONB, not null, default `{}` | `{destination, budget_total, days_count, preferences}` |
| fallback_count | INTEGER, not null, default 0 | consecutive fallback turns (caps LLM fallback cost) |
| trip_id | UUID, FK → trips.id, nullable | ON DELETE SET NULL; set when the plan is generated |
| created_at / updated_at | TIMESTAMPTZ | |

## chat_messages
| Column | Type | Notes |
|---|---|---|
| id | UUID, primary key | |
| seq | BIGINT identity, indexed | total ordering (`now()` is identical for every row of one transaction) |
| session_id | UUID, FK → chat_sessions.id | ON DELETE CASCADE, indexed |
| trip_id | UUID, FK → trips.id, nullable | ON DELETE CASCADE; back-filled for the whole session when the trip is created |
| role | TEXT, not null | `user` \| `assistant` |
| content | TEXT, not null | |
| extracted_fields | JSONB, nullable | the fields newly extracted from this user message |
| created_at | TIMESTAMPTZ | |

Migrations live in `backend/alembic/versions/` and are the source of truth; this file is the readable summary.
